# uu-archive-clickteam-install-creator-v2

Распаковщик архивов **Clickteam Install Creator 2** — самораспаковывающихся
инсталляторов (SFX `.exe`). Проверен на
`Counter-Strike 1.6 (v43) full v.exe` (движок `2.0.0.36`): 6269 файлов,
787.6 MiB, побайтовое совпадение с эталонной распаковкой.

Крейт — библиотека; CLI живёт в `examples/unpack.rs`, поэтому `clap` не
попадает в зависимости библиотеки. Код использует edition 2024 и собирается
на актуальном stable Rust.

## Формат

Инсталлятор — обычный PE-файл, после последней секции которого дописан
оверлей:

```text
+0x00  u32  magic            "wwgT" (0x5467_7777)
+0x04  u32  unknown
+0x08  u16  version          1

       блок   (шрифты/битмапы, без id)
       блок   (u32 id + u32 packed + u32 unpacked + u8 method + данные) ...

u32 0x0000_7F7F              конец секции метаданных
u32 длина потока данных      (повторена дважды)
u8  method                   первый байт потока данных
...                          поток данных до конца файла
```

Каждый блок и каждый файловый блоб состоит из чанков. Чанк начинается с байта
метода: `0` — без сжатия (до конца блоба), `1` — zlib, `2` — bzip2. Это
позволяет смешивать компрессоры в одном блобе.

Таблица файлов — последний блок метаданных. После `0x32`-байтного заголовка и
трёх NUL-terminated строк деинсталлятора идут записи:

```text
[78 байт структура][имя, NUL][необязательные строки ярлыков]
```

Полезные поля структуры: `+0x10` атрибуты, `+0x20` размер, `+0x24` смещение
блоба, `+0x28` сжатый размер, `+0x30` id блоба, `+0x36/+0x3e/+0x46` FILETIME.
Порядок — сначала структура, потом имя; таблица заканчивается «висячим» именем
последнего файла.

## Использование

Готового бинарника в пакете нет: CLI собирается из примера.

```sh
# список содержимого
cargo run --release --example unpack -- installer.exe --list

# распаковать всё в unpacked/
cargo run --release --example unpack -- installer.exe -o cs16

# только файлы из каталога карт
cargo run --release --example unpack -- installer.exe -o maps --filter 'cstrike/maps/*'

# всё поддерево карт, включая вложенные каталоги
cargo run --release --example unpack -- installer.exe -o maps --filter 'cstrike/maps/**'

# плюс внутренние блоки инсталлятора в <output>/_installer
cargo run --release --example unpack -- installer.exe -o cs16 --resources

# не восстанавливать время изменения
cargo run --release --example unpack -- installer.exe --no-times
```

`--filter` понимает glob в стиле оболочки: `*` выбирает файлы внутри одного
каталога, `**` — рекурсивно. Например, `cstrike/maps/*` возьмёт только файлы
непосредственно из `cstrike/maps`, а `cstrike/maps/**` — всё поддерево.
Код возврата: `0` — успех, `1` — были ошибки (или архив не открылся).

## Библиотека

```toml
[dependencies]
uu-archive-clickteam-install-creator-v2 = "0.1"
```

```rust
use std::io::Cursor;

use uu_archive_clickteam_install_creator_v2::{ExtractOptions, Installer};

let bytes = std::fs::read("installer.exe")?;
let mut installer = Installer::new(Cursor::new(bytes))?;

for entry in installer.entries() {
    println!("{} {} -> {}", entry.name, entry.size, entry.offset);
}

installer.extract(std::path::Path::new("out"), &ExtractOptions::default(), |_| {})?;
```

`Installer` принимает любой `Read + Seek`, а данные отдаёт в любой `Write`:

- `copy_entry(&entry, &mut writer)` — потоковая распаковка одной записи;
- `copy_blob(offset, len, &mut writer)` — потоковая распаковка произвольного
  участка потока данных;
- `entry_bytes` / `blob_bytes` — то же самое в `Vec<u8>` для небольших файлов.

В памяти держатся только блоки метаданных (таблица файлов и ресурсы
инсталлятора — сотни килобайт). Файловые блобы декодируются чанк за чанком
прямо в приёмник, поэтому архив любого размера не загружается в память целиком.

`extract` возвращает `ExtractOutcome` с числом успешных/неудачных записей,
суммой байт и списком ошибок; прогресс отдаётся через замыкание-наблюдатель.
Пути санитизируются: `/` и `\` считаются разделителями, `..` заменяется на
`__dotdot__`, недопустимые в Windows символы — на `_`.

## Фаззинг

В репозитории есть отдельный крейт `fuzz/` с тремя целями:

- `installer_open` — разбирает произвольные байты как установщик и потоково
  распаковывает записи с ограничением объёма вывода;
- `entry_stream` — собирает синтетический архив вокруг произвольного блоба и
  проверяет чанковые декодеры;
- `safe_paths` — проверяет инварианты санитизации путей: результат относителен,
  не содержит `..` и корневых компонентов, а повторная обработка его не меняет.

```sh
cargo fuzz run installer_open
cargo fuzz run entry_stream
cargo fuzz run safe_paths
```

В коде нет `unsafe`, `as`-приведений, `unwrap`/`expect` в библиотеке и
CLI (паники исключены; в тестах используются обычные assert-макросы).

## Ограничения

- Поддерживается версия оверлея `1` (Install Creator 2.x). Официальные
  инсталляторы Clickteam с несколькими версиями продукта и зашифрованные
  инсталляторы не проверялись.
- Метаданные ярлыков и реестра сохраняются в таблице, но не интерпретируются:
  распаковываются только файлы и служебные блоки (`--resources`).
- Восстановление времени ограничено диапазоном 1980..2100; мусорные значения
  игнорируются.
